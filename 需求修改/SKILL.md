# 需求修改（lite）

主 Agent 串行干完："澄清&评估 → 同步修改 → 确认"。不建变更单文件、不建影响评估文件、不派调研子 agent。

---

## 适用场景

- 已使用《项目初始化》或《遗留项目接入》完成脚手架
- `项目备忘录.md`、`docs/`、`vault/` 已就位，部分模块可能已完成
- 用户提出新增/修改/删除功能，或调整技术栈、性能等

**不适用：**
- 空项目 → 用《项目初始化》
- 纯代码 bug 修复（无需求变化）→ 走《Bug修复》
- 已完成模块单纯需要改实现 → 走《项目开发》"已完成模块的修改规则"

---

## 前置检查

- [ ] `项目备忘录.md` 存在
- [ ] `docs/需求与架构.md`、`docs/开发进度.md` 存在
- [ ] `vault/` 下有模块任务

任一缺失 → 停止，提示用户先完成初始化或遗留接入。

---

## 阶段一：澄清 & 评估（一轮对话内完成）

### 1.1 澄清变更内容

主动追问必须采用交互式问答提交给用户（必要时给 2-3 个选项让用户挑）：
- **变更类型**：新增 / 修改 / 删除 / 调整非功能要求 / 调整技术栈/依赖 / 调整数据模型或接口
- **变更描述**：具体改成什么、为什么改
- **优先级**：是否阻塞当前开发？是否允许回退已完成模块？

> 不需要建 `docs/变更单/CR-*.md` 这种 ID 化文件。澄清结论直接在对话里复述给用户确认。

### 1.2 评估影响（对话内表格）

主 Agent 自己读 `项目备忘录.md` + 受影响 vault + `docs/需求与架构.md` 相关段（不派子 agent），在**对话里**列出影响清单：

```markdown
## 本次变更影响清单

### 文档影响
- docs/需求与架构.md：[需要改哪段]
- docs/开发进度.md：[哪些行需要回退/新增/删除]
- 项目备忘录.md：[模块依赖图 / 勿动清单 是否需要更新]

### vault 影响
| vault | 当前状态 | 影响 | 处理 |
|---|---|---|---|
| 02-数据模型.md | ✅ 已完成 | 新增字段 X | 从勿动清单移除，回退为 ⬜，建 02a 子任务 |
| 03-认证.md | 🚧 进行中 | 接口签名变化 | 暂停，修改 vault 后重新开始 |
| 06-新模块.md | — | 新建 | 新增 vault 文件 |

### 接口/数据/配置
- 接口（docs/接口.md 或 vault 内接口段）：[新增/修改/删除清单]
- 数据模型：[字段增删]
- .env.example：[新增/删除变量]

### 已完成模块返工评估
（若涉及已完成模块，列出返工范围和风险点；无则写"无"）

### 处理建议顺序
1. 改 docs/需求与架构.md
2. 改 vault
3. 改 项目备忘录.md（依赖图/勿动清单）
4. 改 docs/开发进度.md（状态调整）
```

用交互式问答向用户确认：**"以上是影响范围。是否按此清单同步修改文档？需要调整范围请指出。"**

**用户确认前禁止改任何文件。**

---

## 阶段二：同步修改（主 Agent 串行落盘）

按上一阶段确认的清单**依次改文件**（不并行、不派子 agent）：

1. **改 `docs/需求与架构.md`**：更新对应段落（如有大幅变化，在段首加一行 `> 变更于 YYYY-MM-DD：[一句话]` 留痕）。
2. **改受影响的 vault 文件**：
   - 修改已存在 vault 的相应章节（实现要点 / 接口与类型 / 测试要点等）
   - 新增 vault 文件按《项目初始化》2.3 模板写
   - 删除 vault 文件直接删
   - 对**已完成**的 vault，若需返工，建子任务 vault（如 `02a-用户模型扩展.md`），不要直接改原文件；并在原文件末尾加一行 `> 后续返工见 vault/02a` 留痕
3. **改 `项目备忘录.md`**：
   - 「模块依赖图」按新结构调整
   - 「勿动文件」清单中受影响的项移除
   - 必要时更新文档指针
4. **改 `docs/开发进度.md`**：
   - 已完成 → 回退为 ⬜（或建 02a 子任务行）
   - 进行中 → 标 🚫 阻塞 + 备注"等待变更同步"
   - 新增 → ⬜ 待开发
   - 删除 → 直接移除该行
5. **接口同步**：若有独立的 `docs/接口.md`，同步增删条目；vault 内的接口段也保持一致。
6. **`.env.example`**：增删变量。

每改完一项，**在对话里简短报告"刚改了 XX"**，方便用户跟踪进度。

---

## 阶段三：确认

主 Agent 自己快速跑一遍以下 5 条：

- [ ] vault 中接口段 vs `docs/接口.md`（如有）字段级一致
- [ ] vault 编号 vs `docs/开发进度.md` 行一一对应、无悬空
- [ ] `项目备忘录.md` 模块依赖图 vs vault 的「依赖谁」吻合
- [ ] 删除的 vault 没有被其它文档引用
- [ ] `项目备忘录.md` 仍 ≤ 150 行（超 200 才警告精简）

发现不一致 → 直接修。

完成后告诉用户：

> "需求变更同步完成。可以继续《项目开发》——建议优先处理：[列出新增/回退的关键 vault 编号]。同会话可直接继续，也可清空上下文重新丢《项目开发》+ `项目备忘录.md`。"

---

## 关键提醒

1. **本 skill 不写业务代码**：只改文档；代码层修改交给《项目开发》；若是明确 bug 修复，交给《Bug修复》。
2. **影响评估先于动手**：未列清影响清单前不准改文件。
3. **已完成模块优先用子任务（02a）增量返工**，不要整体回退原 vault，避免破坏已通过的测试。
4. **技术选型仍要用户拍板**：变更涉及多个技术路线时，用交互式问答列 2-3 方案 + 利弊。
5. **不强制 CR 编号**：个人项目不需要建 `docs/变更单/CR-*.md` 文件。
6. **不强制 `docs/修复记录.md` 留档**：在对话里告诉用户一句即可。

---

## 反模式

- ❌ 没列影响清单就直接动文件。
- ❌ 单独建 `docs/变更单/` 给每次变更编 ID。
- ❌ 把"已完成"模块整体回退为 ⬜，无视子任务方案。
- ❌ 只改了 vault 接口段，忘记同步 `docs/接口.md` 或反过来。
- ❌ 在本 skill 里动手写业务代码。
- ❌ 派一堆 R1~R6 / W1~W6 子 agent 走形式（lite 版不要）。
