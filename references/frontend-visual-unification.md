
# 前端视觉统一（lite）

> 内部流程规则：仅由根 `SKILL.md` 根据 `$ARGUMENTS` 通过 `Read` 加载，不可独立调用。

> 本内部流程是前端 Agent 组的视觉决策环节。用户选择视觉方向前，只能生成隔离预览，不得修改正式产品页面、设计 token 或共享组件。

## 触发条件

- 页面规划已基本确定。
- 初始化时尚未有视觉基线，或需求变更影响全局 token、共享组件和页面风格。
- 仅单页小修且已有明确设计基线时，可由《项目开发》按既有契约实现，不重复生成方向。

## 状态机

```text
PREFERENCE → SHARED_BRIEF → PREVIEW_CONFIRM
→ BUILD_DIRECTIONS(3) → CHECK → USER_PICK → DECISION_PACKAGE
```

## 视觉方向规格（核心）

三个方向必须在同一套硬约束维度上可比，禁止用"高端/大气/简洁"这类形容词替代可检查项。每个方向至少固定以下六组硬约束：

1. **配色**：主色 + 辅色 + 点缀色，逐色给出 hex、面积占比（如"白/浅灰 ≥ 70%"，强调色作高冲击色块而非全局底）和每色用途许可/禁令（如"黑色仅用于文字与细线，不得做大面积背景"）。
2. **视觉风格**：风格关键词（如"海报化后台"）＋ 具体手法清单（从下方词汇表选取，逐一列出用或不用）。
3. **布局分区**：左导航 / 顶部栏 / 首屏 / 图表区 / 内容区 / 底部逐区给硬约束，并声明"不得做成传统模板"的具体含义。
4. **风格禁令**：独立成节，明确禁止项（深色主题、玻璃拟态、蓝紫赛博、圆角卡片、平均分栏等），可作为代码审查否决项。
5. **视觉焦点顺序**：显式声明 1→2→3 的层级（如"超大中文标题 → 强调色几何主块 → 信息带 → 数据模块 → 背景英文排版"）。
6. **实现约束**：语义化 HTML5、内联 CSS、Grid/Flex、无外部图片、真实文案、克制动效、桌面优先＋移动适配、系统字体。

### 视觉手法词汇表

方向描述必须落到以下具体手法，禁止只给风格名词：

- 超大背景字（浅灰/极淡灰，允许裁切出屏）
- 细网格线 / 斜线纹理 / 几何切割 / 编号 / 信息条 / 条码感
- 错位数据条 / 横向信息模块 / 叠层标签块 / 跨宽模块 / 模块与标题重叠
- 非对称图表布局 / 细线边框 / 印刷标识式标题
- 大面积信息带（腰封式横向带）

## 阶段一：偏好与共享 brief

先向用户询问品牌/气质、参考偏好、禁用风格、颜色/字体限制、已有组件库、目标用户和中国大陆网络限制。然后固定一份 brief，至少包含：

- 同一个代表页面和相同内容；
- 相同页面结构、用户动作和响应式断点；
- 桌面与移动视口；
- 只允许变化的视觉维度：颜色、字阶、密度、边框/阴影、图标和动效节制；
- 明确不改变信息架构、功能和路由；
- 每个方向必须填满上文「视觉方向规格」六组硬约束，三方向在这些维度上可比。

用户确认 brief 后才能并行生成预览。

## 阶段二：三个隔离预览

生成 3 个互不写入的预览工作单元，各自只写：

```text
agent-output/frontend-visual/<run-id>/direction-a/index.html
agent-output/frontend-visual/<run-id>/direction-b/index.html
agent-output/frontend-visual/<run-id>/direction-c/index.html
```

每个预览必须是可离线直接打开的自包含页面，使用相同 brief、相同内容和相同视口；只能改变视觉方向，且三个方向要在「视觉方向规格」的不同维度上真正产生差异（不是仅换主色 hex）。普通模式可按用户确认的资源条件并行生成 3 个方向；Goal 模式由第 0 层最多同时委派 2 个第 1 层预览 Agent，第三个方向在任一槽位释放后再执行，累计仍生成 3 个。检查工作由归属当前 `ACTIVE` 流程的第 1 层 Agent 完成并向第 0 层返回压缩证据，不得由第 0 层读取完整预览实现。

用户选择前：

- 不修改正式源码、组件库、设计 token 或项目依赖；
- 不把预览当作可上线代码；
- 不删除预览，除非 Goal 启动合同已明确授权该精确目录的清理。

## 中国大陆网络策略

资源优先级：

1. 项目已有本地依赖和资产；
2. 自包含 HTML/CSS、系统字体或本地字体；
3. 锁版本并随项目构建打包的开源依赖；
4. 用户明确授权且带本地 fallback 的在线资源。

默认禁止运行时依赖 Google Fonts、GitHub raw、unpkg、jsDelivr 或其他未确认 CDN。引入开源库或在线资源前检查许可证、维护状态、包体、隐私和替代方案；网络不可用时预览仍应能打开。

## 阶段三：检查与选择

检查每方向是否同时满足：

- 配色给出 hex＋面积占比＋每色用途许可/禁令；
- 风格落到具体手法清单而非形容词；
- 有独立风格禁令节；
- 声明了视觉焦点顺序；
- 三方向在手法或结构上确有差异，不是换色号。

用户选择一个方向后，输出决策包并交给《项目初始化》或《需求修改》串行同步：

```markdown
## 视觉基线交接
- 选定方向：
- 颜色 token（hex＋面积占比＋用途许可/禁令）：
- 字体与字阶：
- 视觉手法清单：
- 视觉焦点顺序：
- 风格禁令：
- 间距、圆角、边框、阴影：
- 图标与控件状态：
- 响应式规则：
- 可访问性要求：
- 共享组件：
- 正式实现范围：
- 预览路径：
```

正式实现由《项目开发》完成。视觉意见只有在用户确认并写入基线后，才能作为代码审查契约；未确认的审美偏好不能制造阻断 finding。

## 完成检查

- [ ] brief 固定且三方向功能/内容/布局可比
- [ ] 每方向填满视觉方向规格六组硬约束
- [ ] 三方向在手法或结构上确有差异（非仅换色）
- [ ] 三个预览目录互不重叠
- [ ] 预览离线打开无关键资源缺失
- [ ] 桌面/移动视口已检查
- [ ] 用户已选择方向
- [ ] 视觉 token、组件状态、响应式和可访问性已形成交接包
- [ ] 正式修改交回初始化/需求修改/项目开发流程

## 反模式

- ❌ 三个方向使用不同页面或不同内容，导致比较失真。
- ❌ 三个方向只在色相上变化，手法、布局、禁令相同。
- ❌ 用"高端/大气/简洁/专业"等形容词替代 hex、手法清单和禁令。
- ❌ 用户未选择就把某个方向写进正式产品。
- ❌ 运行时热链外部字体、图片或 CDN。
- ❌ 只做静态成功态，不验证移动端、焦点、对比度和错误状态。
- ❌ 用个人审美偏好替代用户确认的设计契约。
